# LoL Viewer Wiki データ取得と更新設計

## 1. 文書の目的

本書は、`LoL Viewer Wiki` において Riot 公式データをどう使うか、どこまで自動化するか、どこから手動運用にするかを明確にするための設計文書である。  
フェーズ13では、実装そのものよりも `運用で破綻しない設計` を先に固めることを目的とする。

## 2. 前提

### 2.1 このサイトで扱うデータ

本サイトで扱うデータは、以下の 2 種類に分ける。

1. Riot 公式の静的データ
2. 本サイト独自の手動解説データ

公式データは、チャンピオン名、画像、スキル名、アイテム名、パッチバージョンなどの `事実情報` を支えるために使う。  
一方で、`観戦初心者向けにどう見えるか`、`何が分かりやすいか`、`この変更をどう読むか` は手動で管理する。

### 2.2 今回の設計対象

今回は以下を対象とする。

- Riot 公式の静的データ利用方針の整理
- 自動取得するデータの決定
- 手動管理するデータの決定
- チャンピオン / アイテム / パッチ差分の格納方針

以下は対象外とする。

- プレイヤー個人情報
- 対戦履歴や勝率集計
- マッチ API を使った統計機能
- 本番自動実行基盤の実装

## 3. Riot 公式データの利用方針

### 3.1 今回の方針

`LoL Viewer Wiki` では、当面 `Data Dragon` を主な公式データソースとして使う。

理由:

- チャンピオン
- アイテム
- ルーン
- 画像アセット
- バージョン情報

を静的ファイルとして取得でき、初心者向け静的サイトと相性が良いため。

### 3.2 2026年7月27日時点で確認した公式情報

2026年7月27日（月）時点で、Riot 公式ドキュメントには以下の記載がある。

- League of Legends の `Data Dragon` は、チャンピオン、アイテム、ルーン、サモナースペル、プロフィールアイコンなどのデータとアセットを提供している
- `Data Dragon` の更新は各パッチ後に手動で行われるため、ゲーム本体と同時には更新されないことがある
- バージョン一覧は `versions.json` から取得できる
- 同一パッチでも追加ビルドがあり得るため、常にそのパッチで最も新しい Data Dragon バージョンを使うべきとされている

また、ポリシー面では以下を前提にする。

- プレイヤー向けプロダクトは、公式 documented API を使うかどうかに関係なく Riot Developer Portal への登録が必要
- 使える Riot IP 資産には `Game-Specific static data` が含まれる
- サイト上の見やすい場所に非公式表記の法的文言を掲示する必要がある

### 3.3 本サイトで使う公式ソース

本サイトで使う公式ソースは以下に限定する。

- `https://ddragon.leagueoflegends.com/api/versions.json`
- `https://ddragon.leagueoflegends.com/realms/{region}.json`
- `https://ddragon.leagueoflegends.com/cdn/{version}/data/ja_JP/champion.json`
- `https://ddragon.leagueoflegends.com/cdn/{version}/data/ja_JP/champion/{Champion}.json`
- `https://ddragon.leagueoflegends.com/cdn/{version}/data/ja_JP/item.json`
- `https://ddragon.leagueoflegends.com/cdn/{version}/img/...`

補足:

- 日本語データは `ja_JP` を基本にする
- 画像は必要に応じてローカルへ保存する
- MVP 段階では Data Dragon 以外の Riot API 利用は必須ではない

## 4. 自動取得と手動管理の境界

### 4.1 自動取得するもの

以下は自動取得対象とする。

- 最新 Data Dragon バージョンの検知
- チャンピオン一覧データ
- チャンピオン個別の静的データ
- アイテム一覧データ
- チャンピオン画像、スキル画像、アイテム画像などの静的アセット
- 前回取得バージョンとの差分抽出用の元データ

### 4.2 手動管理するもの

以下は手動管理対象とする。

- 初心者向け解説本文
- チャンピオンごとの `ひとことで言うと`
- `観戦で注目するポイント`
- `おすすめルーン` の説明
- `よくあるアイテム` の説明
- パッチノートのやさしい要約
- `初心者に関係ある変更`
- `観戦で見え方が変わるポイント`

### 4.3 半自動にするもの

以下は `自動抽出 + 手動判断` の半自動対象とする。

- 新パッチ公開の検知
- どのチャンピオン / アイテムが変わったかの一覧化
- 変更量が大きい対象の洗い出し
- MVP 10体に関係する変更だけの抽出

この部分は、人間が要約を書くための下準備として使う。

## 5. 自動化可否の結論

### 自動化できること

- 最新 Data Dragon バージョンを検知する
- 該当バージョンの公式 JSON と画像を取得する
- チャンピオン / アイテムの差分を JSON 同士で比較する
- MVP 10体に関係する変更候補を抽出する
- `latest` に使うパッチ番号候補を特定する

### 自動化しない方がよいこと

- Riot 公式パッチノート本文の丸ごと機械要約
- 初心者向け説明文の自動生成
- ルーン / アイテム構成の自動最適化更新
- `観戦で何を見るべきか` の自動判断

理由:

- 文体の統一が崩れやすい
- 説明責任が持ちにくい
- 初心者向けに本当に重要な情報だけを絞る作業は人間判断の価値が高い

## 6. データ格納方針

### 6.1 現在維持するディレクトリ

- `src/content/champions/`
  - 手動解説
- `src/data/riot/champions/`
  - Riot 公式のチャンピオン静的データ

### 6.2 今後追加する想定ディレクトリ

- `src/data/riot/meta/versions.json`
  - 取得済みバージョン一覧
- `src/data/riot/items/`
  - アイテム静的データ
- `src/data/riot/patches/`
  - パッチ差分の中間生成物

### 6.3 チャンピオンデータの格納形式

チャンピオンデータは、`1チャンピオン = 1ファイル` を維持する。

例:

- `src/data/riot/champions/ahri.json`
- `src/data/riot/champions/ornn.json`

理由:

- 手動解説ファイルとの対応が取りやすい
- MVP 10体だけ先に持つ運用でも扱いやすい
- 差分レビューがしやすい

### 6.4 アイテムデータの格納形式

アイテムデータは、当面 `1バージョン = 1ファイル` を採用する。

例:

- `src/data/riot/items/15-15.json`
- `src/data/riot/items/15-16.json`

理由:

- 全アイテムを個別ファイルへ分解する必要は当面ない
- パッチ差分比較がしやすい
- MVP の `アイテム入門` はカテゴリ説明中心なので、個別ページ単位の細分化を急ぐ必要がない

## 7. パッチ差分の扱い

### 7.1 差分抽出の単位

パッチ差分は以下の 2 系統に分けて扱う。

1. チャンピオン差分
2. アイテム差分

### 7.2 差分の保存形式

差分の保存は、`公開ページ用データ` ではなく `更新補助データ` として持つ。

例:

- `src/data/riot/patches/15-15/champion-diff.json`
- `src/data/riot/patches/15-15/item-diff.json`

想定内容:

- 変更があった対象名
- 変更前バージョン
- 変更後バージョン
- 数値や説明文の変化
- MVP 10体に含まれるかどうか

### 7.3 公開ページへの反映方針

差分 JSON をそのまま公開ページへ出すことはしない。  
差分 JSON は、パッチ要約を書く時の下書き資料としてのみ使う。

公開ページには以下だけを載せる。

- 初心者に関係ある変更
- 観戦で見え方が変わるポイント
- 主要なチャンピオン / アイテム変更

## 8. 更新フローの設計

### 8.1 パッチ更新時の基本フロー

1. `versions.json` を確認して新バージョンを検知する
2. 該当バージョンの Data Dragon を取得する
3. チャンピオン / アイテム差分を抽出する
4. MVP 10体と初心者向け重要カテゴリに関係する変更だけを確認する
5. 手動でパッチ要約を書く
6. `latest` を更新する

### 8.2 チャンピオン更新時の基本フロー

1. 公式チャンピオンデータを更新する
2. スキル名、画像、基本情報の変化を確認する
3. 必要なチャンピオンだけ手動解説を見直す
4. `おすすめルーン` と `よくあるアイテム` が古く見えないか確認する

## 9. このフェーズの結論

フェーズ13の結論は以下である。

- Riot 公式データは `Data Dragon` を中心に使う
- チャンピオン / アイテム /画像 / バージョン検知は自動化対象にする
- 初心者向け説明文とパッチ要約は手動管理を維持する
- パッチ差分は公開用ではなく、要約作成の補助データとして保存する
- MVP 段階では、マッチ API や個人プレイヤーデータは扱わない
