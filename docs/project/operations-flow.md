# LoL Viewer Wiki 運用フロー整備

## 1. 文書の目的

本書は、`LoL Viewer Wiki` の更新作業を、誰が見ても同じ手順で進められるようにするための運用手順書である。  
フェーズ14では、`新パッチ対応`、`チャンピオン解説の見直し`、`本文更新時の確認観点` を整理する。

## 2. 運用の前提

- 公式データは Riot の `Data Dragon` を基準に確認する
- 初心者向け本文は手動で更新する
- `最新パッチのやさしい要約` は、公開中サイトで常に 1 本を主軸にする
- 更新の優先順位は `事実情報の反映` より `初心者が見て分かりやすいこと` を優先する

## 3. 新パッチ公開時の更新手順

### 3.1 全体フロー

新パッチ公開時は、以下の順で進める。

1. 新パッチの有無を確認する
2. Data Dragon の最新バージョンを確認する
3. チャンピオン差分 / アイテム差分を確認する
4. MVP 10体と初心者向け主要カテゴリへの影響を確認する
5. パッチ要約原稿を書く
6. `latest` で見せるパッチを更新する
7. 表示確認して公開する

### 3.2 詳細手順

#### 1. 新パッチの有無を確認する

確認対象:

- Riot 公式パッチ情報
- Data Dragon の `versions.json`

確認内容:

- 新しいパッチ番号が出ているか
- Data Dragon 側で利用可能になっているか

補足:

- Data Dragon はゲーム本体と同時更新ではないことがあるため、`パッチが出た = すぐ更新可能` とは限らない

#### 2. Data Dragon の最新バージョンを確認する

確認内容:

- そのパッチ番号に対応する最新 Data Dragon バージョン
- 同一パッチ内に追加ビルドがないか

運用ルール:

- 同一パッチで複数ビルドがある場合は、一番新しいものを採用する

#### 3. チャンピオン差分 / アイテム差分を確認する

確認対象:

- チャンピオン個別 JSON
- アイテム一覧 JSON

見るポイント:

- どのチャンピオンが変わったか
- どのアイテムが変わったか
- MVP 10体に含まれるか
- 初心者向けに見え方が変わる変更か

#### 4. MVP 10体と主要カテゴリへの影響を確認する

優先確認対象:

- MVP 10体
- `エンゲージ`
- `集団戦`
- `ローム`
- `ゴールド`
- `アイテム入門`

判断基準:

- 観戦時の見どころが変わるか
- チャンピオン個別ページの説明が古く見えるか
- アイテム入門のカテゴリ説明に影響するか

#### 5. パッチ要約原稿を書く

最低限入れるもの:

- 今回のパッチをひとことで
- 今回のパッチの全体像
- 初心者に関係ある変更
- 観戦で見え方が変わるポイント
- 主なチャンピオン変更
- 主なアイテム変更
- 初心者向けメモ

書かない方がよいもの:

- 数値差分の大量列挙
- 初心者に関係が薄い細かい変更
- 断定的なメタ評価

#### 6. `latest` で見せるパッチを更新する

更新対象:

- `src/content/patch-notes/`
- `src/pages/patch-notes/latest.astro`

運用ルール:

- `latest` は常に公開中で最も新しい要約へ向ける
- 過去パッチは必要最小限のみ残す

#### 7. 表示確認して公開する

最低限確認する項目:

- `npm run check`
- `npm run build`
- `/patch-notes/`
- `/patch-notes/latest/`
- 該当パッチ個別ページ
- 関連チャンピオンへのリンク
- 関連用語へのリンク

## 4. `新パッチ確認 → 差分確認 → 要約作成 → 公開` の標準フロー

このサイトにおける標準更新フローは以下とする。

1. 新パッチ確認
2. 公式静的データ更新
3. 差分確認
4. 要約対象の絞り込み
5. やさしい要約作成
6. 関連ページの軽微見直し
7. ビルド確認
8. PR 作成
9. マージ / 公開

### 4.1 要約対象の絞り込みルール

毎回すべての変更を書くのではなく、以下の優先順で拾う。

1. MVP 10体に関係する変更
2. 観戦の見え方が変わる変更
3. 初心者が配信で気づきやすい変更
4. アイテム入門や用語集に波及する変更

## 5. チャンピオンごとのルーン見直しフロー

### 5.1 見直しが必要になる条件

以下のいずれかに当てはまる時だけ見直す。

- MVP 10体に直接調整が入った
- 関連する主要アイテムに調整が入った
- 代表ルーンの説明が不自然になるほどプレイ意図が変わった

### 5.2 見直しの順番

1. そのチャンピオンのパッチ差分を確認する
2. 関連アイテム変更の有無を確認する
3. `おすすめルーン` の説明文がまだ成立するか確認する
4. `よくあるアイテム` の説明文がまだ成立するか確認する
5. `観戦で注目するポイント` にズレがないか確認する

### 5.3 更新時の判断ルール

- ルーン名だけを機械的に差し替えない
- `なぜそのルーンなのか` を説明できる場合だけ更新する
- 初心者向け代表例として不自然でなければ、毎パッチ細かく追いかけすぎない

## 6. 解説文更新時のチェック観点

本文更新時は、以下を毎回確認する。

### 6.1 内容面

- 初心者が読んで意味が分かるか
- 難しい用語を説明なしで使いすぎていないか
- 観戦目線で読む価値があるか
- 数値説明に偏りすぎていないか

### 6.2 整合性

- 関連用語リンクが今の内容と合っているか
- ロール、オブジェクト、チャンピオンページ間で矛盾していないか
- 最新パッチ要約と個別ページ説明が食い違っていないか

### 6.3 表現

- 文体が既存ページと揃っているか
- `ひとことで言うと`
- `ここだけ覚えればOK`
- `観戦ではここを見る`

などの定型見出しが崩れていないか

### 6.4 表示

- モバイルで段落が長すぎないか
- リンク切れがないか
- 一覧ページから目的ページへ辿れるか

## 7. 更新頻度の考え方

### 7.1 毎パッチ確認するもの

- 最新パッチ要約
- MVP 10体に関係する変更
- アイテム入門に影響する大きな変更

### 7.2 必要時のみ見直すもの

- ロール解説
- オブジェクト解説
- はじめて見る人向けページ

理由:

これらはパッチごとの数値調整では崩れにくく、ゲームの基本構造が変わらない限り頻繁な更新を必要としないため。

## 8. このフェーズの結論

フェーズ14の運用ルールは以下とする。

- 新パッチ時は `確認 → 差分抽出 → 要約作成 → latest 更新 → 公開` の順で進める
- すべての変更を追うのではなく、`初心者に見え方の差が出る変更` を優先する
- ルーン / アイテムは毎回全面更新せず、説明が崩れる時だけ見直す
- 本文更新時は `内容面 / 整合性 / 表現 / 表示` の4軸で確認する
